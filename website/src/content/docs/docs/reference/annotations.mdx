OptiPod uses Kubernetes annotations to store recommendations and metadata on workloads. This page provides a complete reference for all annotations used by OptiPod.

## Management Annotations

### optipod.io/managed

**Type:** string
**Values:** `"true"`
**Applied to:** Workload resources (Deployment, StatefulSet, DaemonSet)
**Set by:** OptiPod operator
**Mode:** All modes

Indicates that this workload is managed by OptiPod.

**Example:**
```yaml
annotations:
  optipod.io/managed: "true"
```

### optipod.io/policy

**Type:** string
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** All modes

Name of the OptimizationPolicy managing this workload.

**Example:**
```yaml
annotations:
  optipod.io/policy: "production-policy"
```

### optipod.io/policy-uid

**Type:** string (UID)
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** All modes

Unique identifier of the OptimizationPolicy managing this workload.

**Example:**
```yaml
annotations:
  optipod.io/policy-uid: "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
```

## Timestamp Annotations

### optipod.io/last-recommendation

**Type:** RFC3339 timestamp
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** All modes

Timestamp when the recommendation was last updated.

**Example:**
```yaml
annotations:
  optipod.io/last-recommendation: "2026-01-26T10:30:00Z"
```

### optipod.io/last-applied

**Type:** RFC3339 timestamp
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** Auto mode only

Timestamp when OptiPod last applied a recommendation to this workload.

**Example:**
```yaml
annotations:
  optipod.io/last-applied: "2026-01-26T10:30:00Z"
```

## Resource Recommendation Annotations

OptiPod stores resource recommendations as separate annotations for each container and resource type.

### Format

The annotation format is: `optipod.io/recommendation.<container-name>.<resource-type>`

Where:
- `<container-name>` is the name of the container
- `<resource-type>` is one of: `cpu-request`, `memory-request`, `cpu-limit`, `memory-limit`

### optipod.io/recommendation.&lt;container-name&gt;.cpu-request

**Type:** Kubernetes resource quantity
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** All modes

Recommended CPU request for the specified container.

**Example:**
```yaml
annotations:
  optipod.io/recommendation.nginx.cpu-request: "250m"
  optipod.io/recommendation.sidecar.cpu-request: "50m"
```

### optipod.io/recommendation.&lt;container-name&gt;.memory-request

**Type:** Kubernetes resource quantity
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** All modes

Recommended memory request for the specified container.

**Example:**
```yaml
annotations:
  optipod.io/recommendation.nginx.memory-request: "512Mi"
  optipod.io/recommendation.sidecar.memory-request: "128Mi"
```

### optipod.io/recommendation.&lt;container-name&gt;.cpu-limit

**Type:** Kubernetes resource quantity
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** All modes

Recommended CPU limit for the specified container.

**Example:**
```yaml
annotations:
  optipod.io/recommendation.nginx.cpu-limit: "500m"
  optipod.io/recommendation.sidecar.cpu-limit: "100m"
```

### optipod.io/recommendation.&lt;container-name&gt;.memory-limit

**Type:** Kubernetes resource quantity
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** All modes

Recommended memory limit for the specified container.

**Example:**
```yaml
annotations:
  optipod.io/recommendation.nginx.memory-limit: "1Gi"
  optipod.io/recommendation.sidecar.memory-limit: "256Mi"
```

## Webhook Strategy Annotations

### optipod.io/webhook-enabled

**Type:** string
**Values:** `"true"`
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** Auto mode with webhook strategy

Indicates that the webhook should process pods from this workload.

**Example:**
```yaml
annotations:
  optipod.io/webhook-enabled: "true"
```

### optipod.io/strategy

**Type:** string
**Values:** `"webhook"`, `"ssa"`
**Applied to:** Workload resources
**Set by:** OptiPod operator
**Mode:** All modes

Indicates which update strategy is used for this workload.

**Example:**
```yaml
annotations:
  optipod.io/strategy: "webhook"
```

## Complete Example

Here's what a fully annotated deployment looks like:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  namespace: production
  annotations:
    # Management annotations
    optipod.io/managed: "true"
    optipod.io/policy: "production-policy"
    optipod.io/policy-uid: "a1b2c3d4-e5f6-7890-abcd-ef1234567890"

    # Timestamp annotations
    optipod.io/last-recommendation: "2026-01-26T10:30:00Z"
    optipod.io/last-applied: "2026-01-26T10:35:00Z"

    # Resource recommendations for 'nginx' container
    optipod.io/recommendation.nginx.cpu-request: "250m"
    optipod.io/recommendation.nginx.memory-request: "512Mi"
    optipod.io/recommendation.nginx.cpu-limit: "500m"
    optipod.io/recommendation.nginx.memory-limit: "1Gi"

    # Resource recommendations for 'sidecar' container
    optipod.io/recommendation.sidecar.cpu-request: "50m"
    optipod.io/recommendation.sidecar.memory-request: "128Mi"
    optipod.io/recommendation.sidecar.cpu-limit: "100m"
    optipod.io/recommendation.sidecar.memory-limit: "256Mi"

    # Strategy annotations
    optipod.io/webhook-enabled: "true"
    optipod.io/strategy: "webhook"
spec:
  # ... deployment spec
```

## Querying Annotations

### Get All OptiPod Annotations

```bash
kubectl get deployment my-app -o json | \
  jq '.metadata.annotations | with_entries(select(.key | startswith("optipod.io/")))'
```

### Get Recommendations for Specific Container

```bash
# CPU request
kubectl get deployment my-app \
  -o jsonpath='{.metadata.annotations.optipod\.io/recommendation\.nginx\.cpu-request}'

# Memory request
kubectl get deployment my-app \
  -o jsonpath='{.metadata.annotations.optipod\.io/recommendation\.nginx\.memory-request}'
```

### Get Last Recommendation Time

```bash
kubectl get deployment my-app \
  -o jsonpath='{.metadata.annotations.optipod\.io/last-recommendation}'
```

### Get Managing Policy

```bash
kubectl get deployment my-app \
  -o jsonpath='{.metadata.annotations.optipod\.io/policy}'
```

### List All Containers with Recommendations

```bash
kubectl get deployment my-app -o json | \
  jq -r '.metadata.annotations | keys[] | select(startswith("optipod.io/recommendation.")) | select(contains(".cpu-request")) | split(".")[1]' | sort -u
```

## Annotation Lifecycle

### Recommend Mode

In Recommend mode, OptiPod sets:
1. `optipod.io/managed: "true"`
2. `optipod.io/policy: "<policy-name>"`
3. `optipod.io/policy-uid: "<policy-uid>"`
4. `optipod.io/last-recommendation: "<timestamp>"`
5. Resource recommendation annotations for each container
6. `optipod.io/strategy: "webhook"` or `"ssa"`

### Auto Mode with Webhook Strategy

In Auto mode with webhook strategy, OptiPod additionally sets:
1. `optipod.io/webhook-enabled: "true"`
2. `optipod.io/last-applied: "<timestamp>"` (after applying)

The webhook reads these annotations and applies them to pods at creation time.

### Auto Mode with SSA Strategy

In Auto mode with SSA strategy, OptiPod:
1. Sets all recommendation annotations
2. Uses Server-Side Apply to update the workload spec directly
3. Sets `optipod.io/last-applied: "<timestamp>"`
4. Sets `optipod.io/strategy: "ssa"`

## GitOps Compatibility

OptiPod's annotation strategy is designed to be GitOps-safe:

- **Annotations are stored on workload metadata**, not in pod templates
- **ArgoCD and Flux ignore metadata annotations** by default
- **Webhook applies resources at runtime**, so pod templates remain unchanged
- **No conflicts with GitOps controllers**

This means you can:
1. Store your deployment YAMLs in Git without resource requests/limits
2. Let OptiPod manage resources via annotations
3. Let your GitOps tool manage everything else
4. No fighting between OptiPod and GitOps

## Annotation Cleanup

When a policy is deleted or a workload no longer matches any policy:
- OptiPod **does not** automatically remove annotations
- Existing recommendations remain on the workload
- You can manually remove annotations if desired

To manually remove all OptiPod annotations:

```bash
# Remove all optipod.io/* annotations
kubectl annotate deployment my-app \
  $(kubectl get deployment my-app -o json | \
    jq -r '.metadata.annotations | keys[] | select(startswith("optipod.io/")) | . + "-"' | \
    tr '\n' ' ')
```

## Best Practices

1. **Don't manually edit recommendation annotations** - Let OptiPod manage them
2. **Use `kubectl describe`** to view annotations in human-readable format
3. **Monitor `last-recommendation` timestamps** to ensure policies are active
4. **Check `policy` annotation** to understand which policy is managing a workload
5. **Use labels for opt-in**, not annotations (labels are for selection, annotations for metadata)

## Troubleshooting

### No Annotations Appearing

Check:
- Workload matches policy selector (labels, namespace, workload type)
- Policy is in correct namespace
- Sufficient metrics data available
- Policy status: `kubectl describe optimizationpolicy <name>`

### Annotations Not Being Applied by Webhook

Verify:
- `optipod.io/webhook-enabled: "true"` is set
- Webhook is deployed and running
- Webhook has valid TLS certificates
- Check webhook logs for errors

### Stale Recommendations

Check:
- `last-recommendation` timestamp
- Policy reconciliation interval
- Metrics provider connectivity
