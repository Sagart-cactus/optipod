This page provides the complete technical specification for the OptimizationPolicy Custom Resource Definition (CRD).

## CRD Metadata

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: optimizationpolicies.optipod.optipod.io
spec:
  group: optipod.optipod.io
  versions:
    - name: v1alpha1
      served: true
      storage: true
  scope: Namespaced
  names:
    plural: optimizationpolicies
    singular: optimizationpolicy
    kind: OptimizationPolicy
    shortNames:
      - optpol
```

## Complete Spec Schema

### Required Fields

```yaml
spec:
  required:
    - mode
    - selector
    - metricsConfig
    - resourceBounds
    - updateStrategy
```

### spec.mode

**Type:** string
**Required:** Yes
**Enum:** `Recommend`, `Auto`, `Disabled`

Operational mode for the policy.

```yaml
mode: Recommend
```

### spec.weight

**Type:** integer
**Required:** No
**Default:** 100
**Range:** 1-1000

Priority when multiple policies match the same workload. Higher weight wins.

```yaml
weight: 200
```

### spec.selector

**Type:** object
**Required:** Yes

Defines which workloads this policy applies to.

```yaml
selector:
  type: object
  properties:
    workloadSelector:
      type: object
      description: Label selector for workloads
      properties:
        matchLabels:
          type: object
          additionalProperties:
            type: string
        matchExpressions:
          type: array
          items:
            type: object
            required:
              - key
              - operator
            properties:
              key:
                type: string
              operator:
                type: string
                enum: [In, NotIn, Exists, DoesNotExist]
              values:
                type: array
                items:
                  type: string

    namespaceSelector:
      type: object
      description: Label selector for namespaces
      # Same structure as workloadSelector

    namespaces:
      type: object
      description: Allow/deny lists for namespaces
      properties:
        allow:
          type: array
          items:
            type: string
        deny:
          type: array
          items:
            type: string

    workloadTypes:
      type: object
      description: Include/exclude filters for workload types
      properties:
        include:
          type: array
          items:
            type: string
            enum: [Deployment, StatefulSet, DaemonSet]
        exclude:
          type: array
          items:
            type: string
            enum: [Deployment, StatefulSet, DaemonSet]
```

**Example:**
```yaml
selector:
  workloadSelector:
    matchLabels:
      optipod.io/enabled: "true"
  workloadTypes:
    include:
      - Deployment
      - StatefulSet
  namespaces:
    allow:
      - production
      - staging
    deny:
      - kube-system
```

### spec.metricsConfig

**Type:** object
**Required:** Yes

Configuration for metrics collection and processing.

```yaml
metricsConfig:
  type: object
  required:
    - provider
  properties:
    provider:
      type: string
      enum: [prometheus, metrics-server, custom]
      description: Metrics backend

    rollingWindow:
      type: string
      default: "24h"
      description: Time period for metrics aggregation
      pattern: '^[0-9]+(d|h|m|s)$'

    percentile:
      type: string
      enum: [P50, P90, P99]
      default: "P90"
      description: Percentile for recommendations

    safetyFactor:
      type: number
      default: 1.2
      minimum: 1.0
      description: Multiplier applied to percentile

    metricsServer:
      type: object
      description: metrics-server specific configuration
      properties:
        minSamplesRequired:
          type: integer
          minimum: 1
          maximum: 100000
          description: Minimum samples before recommendations
```

**Example:**
```yaml
metricsConfig:
  provider: prometheus
  rollingWindow: 7d
  percentile: P90
  safetyFactor: 1.2
```

### spec.resourceBounds

**Type:** object
**Required:** Yes

Minimum and maximum constraints for recommendations.

```yaml
resourceBounds:
  type: object
  required:
    - cpu
    - memory
  properties:
    cpu:
      type: object
      required:
        - min
        - max
      properties:
        min:
          type: string
          x-kubernetes-int-or-string: true
          description: Minimum CPU (e.g., "10m", "0.1")
        max:
          type: string
          x-kubernetes-int-or-string: true
          description: Maximum CPU (e.g., "4000m", "4")

    memory:
      type: object
      required:
        - min
        - max
      properties:
        min:
          type: string
          x-kubernetes-int-or-string: true
          description: Minimum memory (e.g., "64Mi", "1Gi")
        max:
          type: string
          x-kubernetes-int-or-string: true
          description: Maximum memory (e.g., "8Gi", "16Gi")
```

**Example:**
```yaml
resourceBounds:
  cpu:
    min: 10m
    max: 4000m
  memory:
    min: 64Mi
    max: 8Gi
```

### spec.updateStrategy

**Type:** object
**Required:** Yes

Defines how resource updates are applied.

```yaml
updateStrategy:
  type: object
  properties:
    strategy:
      type: string
      enum: [ssa, webhook]
      default: "webhook"
      description: Update strategy type

    rolloutStrategy:
      type: string
      enum: [immediate, onNextRestart]
      default: "onNextRestart"
      description: When changes take effect (webhook only)

    useServerSideApply:
      type: boolean
      default: true
      description: Enable Server-Side Apply

    updateRequestsOnly:
      type: boolean
      default: true
      description: Update only requests, not limits

    allowInPlaceResize:
      type: boolean
      default: true
      description: Enable in-place pod resize

    allowRecreate:
      type: boolean
      default: false
      description: Allow pod recreation if resize fails

    allowUnsafeMemoryDecrease:
      type: boolean
      default: false
      description: Disable memory safety checks

    limitConfig:
      type: object
      description: How limits are calculated from requests
      properties:
        cpuLimitMultiplier:
          type: number
          default: 1.0
          minimum: 1.0
          maximum: 10.0
          description: CPU limit = request × multiplier
        memoryLimitMultiplier:
          type: number
          default: 1.1
          minimum: 1.0
          maximum: 10.0
          description: Memory limit = request × multiplier

    gradualDecreaseConfig:
      type: object
      description: Gradual memory reduction configuration
      properties:
        enabled:
          type: boolean
          default: false
          description: Enable gradual decrease
        memoryDecreasePercentage:
          type: integer
          default: 10
          minimum: 1
          maximum: 50
          description: Max decrease per reconciliation (%)
        minimumDecreaseThreshold:
          type: string
          x-kubernetes-int-or-string: true
          description: Minimum decrease to trigger gradual mode
        maximumTotalDecrease:
          type: integer
          default: 70
          minimum: 1
          maximum: 90
          description: Max total decrease from original (%)
```

**Example:**
```yaml
updateStrategy:
  strategy: ssa
  rolloutStrategy: onNextRestart
  useServerSideApply: true
  updateRequestsOnly: true
  allowUnsafeMemoryDecrease: false
  limitConfig:
    cpuLimitMultiplier: 1.0
    memoryLimitMultiplier: 1.1
  gradualDecreaseConfig:
    enabled: true
    memoryDecreasePercentage: 10
    minimumDecreaseThreshold: 100Mi
    maximumTotalDecrease: 70
```

### spec.reconciliationInterval

**Type:** string (duration)
**Required:** No
**Default:** "5m"

How often the policy is evaluated.

```yaml
reconciliationInterval: 5m
```

## Complete Example

```yaml
apiVersion: optipod.optipod.io/v1alpha1
kind: OptimizationPolicy
metadata:
  name: production-policy
  namespace: production
spec:
  mode: Auto
  weight: 150

  selector:
    workloadSelector:
      matchLabels:
        optipod.io/enabled: "true"
    workloadTypes:
      include:
        - Deployment
        - StatefulSet
    namespaces:
      allow:
        - production

  metricsConfig:
    provider: prometheus
    rollingWindow: 7d
    percentile: P90
    safetyFactor: 1.2

  resourceBounds:
    cpu:
      min: 10m
      max: 4000m
    memory:
      min: 64Mi
      max: 8Gi

  updateStrategy:
    strategy: ssa
    rolloutStrategy: onNextRestart
    useServerSideApply: true
    updateRequestsOnly: true
    allowUnsafeMemoryDecrease: false
    limitConfig:
      cpuLimitMultiplier: 1.0
      memoryLimitMultiplier: 1.1
    gradualDecreaseConfig:
      enabled: true
      memoryDecreasePercentage: 10
      minimumDecreaseThreshold: 100Mi
      maximumTotalDecrease: 70

  reconciliationInterval: 5m

status:
  conditions:
    - type: Ready
      status: "True"
      lastTransitionTime: "2026-01-26T10:30:00Z"
      reason: PolicyActive
      message: Policy is active and processing workloads
  workloadsDiscovered: 5
  workloadsProcessed: 5
  lastReconciliation: "2026-01-26T10:30:00Z"
  workloadsByType:
    deployments: 3
    statefulSets: 2
    daemonSets: 0
```

## Validation Rules

OptiPod performs the following validations:

1. **Mode**: Must be one of `Recommend`, `Auto`, or `Disabled`
2. **Selector**: At least one selector must be specified
3. **Resource Bounds**: Min must be less than or equal to max
4. **Safety Factor**: Must be >= 1.0
5. **Weight**: Must be between 1 and 1000
6. **Strategy**: Must be `ssa` or `webhook`
7. **Rollout Strategy**: Must be `immediate` or `onNextRestart`
8. **Gradual Decrease**: Percentages must be within valid ranges

```yaml
apiVersion: rbac.authorization.k8s.io/v1

metadata:

  - apiGroups: ["optipod.optipod.io"]
    resources: ["optimizationpolicies/status"]
    verbs: ["get", "update", "patch"]
```
